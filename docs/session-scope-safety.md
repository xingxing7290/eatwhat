# 标签页账号和家庭切换保护

Web 页面将自己的请求绑定到打开时的账号令牌以及已知用户、家庭编号。其他标签页更换令牌，或通过共享的浏览器存储切换已知账号/家庭时，旧页面会显示提示并暂停新的受保护 API 请求；已输入的草稿留在页面，用户可先复制，再自行确认重新加载。已发出的请求仍可能在服务端完成；检测到变更后才到达的响应不会被旧页面当作当前数据使用，涉及写入时应核对结果。登录和注册请求不受此保护拦截；本页正常登录或完成家庭切换后会更新绑定。

新版页面在每次受保护业务请求之前验证 `auth/household-scope` 是否明确支持家庭校验，并携带当前家庭编号；同时发出的核验会合并。验证不通过、网络异常或本地缺少家庭编号时，业务请求不会发送，页面保留草稿并提供重新检查及重新登录入口。新版服务在认证后、上传处理之前检查 `X-Eatwhat-Household`，并在读取家庭上下文时再次核对；不一致时返回 `HOUSEHOLD_SCOPE_CHANGED`。这可以在下一次请求时发现另一设备已完成的家庭切换，但不是主动推送通知。登录和注册不需要此核验。服务端仍接收不带请求头的旧客户端以保持兼容，因此旧客户端不具备同等保护；旧服务缺少能力接口，新版页面不会将其视为受保护服务。

这些检查不是事务屏障：能力核验与业务请求之间仍有时间间隔，服务器可能发生切换或降级；家庭切换和已通过校验的请求也可能并发，后者仍可能在旧家庭完成。涉及写入时应核对结果，服务端的家庭范围校验、版本控制和幂等保护仍然必要。新增核验会增加请求次数和网络延迟；生产代理和 CDN 不应缓存能力接口或私有 API。浏览器存储被清除或禁用、资料缺少家庭编号时，页面需要重新登录。访客点菜页是独立的公开页面，不使用这一登录会话机制。

如果切换家庭请求的响应丢失，服务端可能已经完成切换；旧家庭的下一次核验会被拒绝，此时先保留需要的内容，再通过提示重新登录以取得当前家庭信息。不要重复提交加入请求来猜测结果。
