# 标签页账号和家庭切换保护

Web 页面将自己的请求绑定到打开时的账号令牌以及已知用户、家庭编号。其他标签页更换令牌，或通过共享的浏览器存储切换已知账号/家庭时，旧页面会显示提示并暂停新的受保护 API 请求；已输入的草稿留在页面，用户可先复制，再自行确认重新加载。已发出的请求仍可能在服务端完成；检测到变更后才到达的响应不会被旧页面当作当前数据使用，涉及写入时应核对结果。登录和注册请求不受此保护拦截；本页正常登录或完成家庭切换后会更新绑定。

新版页面在已知有效家庭编号时向新版服务发送 `X-Eatwhat-Household`。服务端在认证后、上传处理之前检查当前用户所属家庭，并在读取家庭上下文时再次核对；不一致时返回 `HOUSEHOLD_SCOPE_CHANGED`，页面暂停后续请求并提供重新登录入口。这可以在下一次请求时发现另一设备已完成的家庭切换，但不是主动推送通知。服务端接收不带该请求头的旧客户端以保持兼容，旧服务会忽略新请求头，因此只有前后端都升级且页面持有正确家庭编号时才有这一保护。

这些检查不是事务屏障：家庭切换和已通过校验的请求可能并发，后者仍可能在旧家庭完成；涉及写入时应核对结果。服务端的家庭范围校验、版本控制和幂等保护仍然必要。浏览器存储被清除或禁用、资料缺少家庭编号时，保护能力受限。访客点菜页是独立的公开页面，不使用这一登录会话机制。
