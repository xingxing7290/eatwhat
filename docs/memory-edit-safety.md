# 饭后回忆编辑与兼容性

新版 Web 只在服务器明确提供条件编辑能力和有效版本时允许编辑回忆。每次应用层写入更新修订标记，编辑提交以家庭、记录、修订标记和更新时间进行条件匹配；版本冲突时不覆盖已有记录，页面保留草稿。响应不确定时，页面直接读取该条回忆核对，避免最近 200 条列表截断造成误判。同一版本的重试与原请求最多只有一次条件更新成功。

编辑器只提交改动过的字段；未改动的照片、菜品和参与成员保留在服务器。移除照片只移除回忆中的引用，不会删除上传文件。历史记录缺少修订标记和更新时间时以 `null` 匹配缺失值，不要求批量迁移。

新版时间线和直接编辑读取可选择保留不可用菜品的位置，页面显示提示并禁止修改相关菜品，直到用户明确确认清除不可用引用；修改文字或照片时原引用保持不变。旧客户端的默认列表和详情格式不变；若服务器不支持完整性标记，新 Web 只允许编辑其他字段。旧客户端自行替换菜品列表仍可能丢失不可见引用，不能将此保护视为所有客户端的事务保证。

新版 Web 删除回忆也要求服务器明确提供 `supportsConditionalDelete`，并携带原版本。若记录在确认期间被编辑或删除，条件删除不会匹配，页面提示刷新核对；缺少此能力的旧服务器上删除按钮会禁用。删除回忆只删除数据库记录，不会自动清理上传文件。

删除冲突或响应不确定时，页面按回忆编号直接读取目标记录，不依赖当前筛选或页码；直接读取或列表刷新失败时保留限制并允许重试。即使核对时记录仍存在，之前的请求也可能稍后完成，提示不会将当前结果当作最终保证。

旧客户端仍可不带版本更新或删除，服务器会在更新时生成新修订标记，使新版 Web 中已打开的旧草稿发生冲突；但旧客户端自身的无条件操作仍可能覆盖或删除其他人的更新。直接数据库写入、绕过应用层钩子的批量操作或同时运行未升级的旧服务器，也不受该修订标记保护。部署前应保留私有备份并在隔离环境验证历史记录、家庭隔离和上传图片；不要自动修改即将到期的旧服务器。

新版时间线通过可选的 `view=timeline` 接口按家庭分页，并可按月份、餐次、有无照片以及回忆文本筛选；旧接口仍返回最多 200 条数组。若连接旧服务器，页面会说明达到上限时仅能在已返回记录内筛选，避免误以为历史记录不存在。分页不是跨请求快照，其他成员同时更改记录时，记录可能在不同页之间移动。创建结果不确定时，必须按日期和内容核对筛选条件及所有相关页面；未显示并不能证明保存失败。

回忆的创建者、参与者与关联菜品只返回当前家庭内仍可访问的引用；历史记录引用了其他家庭成员时，创建者显示为空，不暴露对方账户资料。
