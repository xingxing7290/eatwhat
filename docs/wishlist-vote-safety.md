# 想吃清单投票与兼容性

新版 Web 仅在服务端返回 `supportsSetVote` 和当前用户投票状态时开放投票，使用 `PUT /wishlist/:id/vote` 和布尔值明确设置或取消自己的票。服务端对当前家庭记录使用原子 `$addToSet` / `$pull`，同一目标状态的重复请求不会增加重复票，不同成员的投票也不会通过整数组覆盖彼此。列表中的菜品、创建者和投票成员只填充当前家庭范围内的引用。

旧客户端的 `POST /wishlist/:id/vote` 仍保留切换语义，改为原子数组操作以避免不同成员覆盖彼此；该切换接口本身不是幂等的，重复提交仍可能再次切换。旧服务器未声明新能力时，新版 Web 暂不开放投票，避免将旧切换接口当作幂等操作使用。

投票、状态或删除响应不确定时，页面要求刷新并核对；一次刷新不能保证先前网络请求不会随后完成。状态切换和删除目前没有版本条件，仍可能与其他设备上的并发操作相互影响。临时核对提示保存在当前页面，不是持久的操作日志。部署前应备份并在隔离环境验证新旧客户端及家庭数据；不要自动改动即将到期的旧服务器。
