# 纪念日菜单编辑与兼容性

Web 编辑器只在服务器明确返回 `supportsConditionalEdit` 和有效的 `editVersion` 时允许编辑。提交时携带原版本；服务器以家庭、记录、修订标记和更新时间进行条件更新，并为每次应用层写入生成新的修订标记。冲突返回 409，页面保留草稿，要求用户核对最新菜单。响应丢失时，同一版本的重试与原请求最多只有一次条件更新成功。

编辑器只提交更改过的餐次和照片列表，其他字段保留服务器原值。移除照片只移除菜单中的引用，不会删除上传文件。旧数据没有修订标记或更新时间时，使用 `null` 匹配缺失值，不需要批量迁移。

新版 Web 通过可选的 `view=editor` 列表识别已删除或不属于当前家庭的菜品：原位置以空值保留并显示“菜品不可用”，创建者资料也按家庭过滤。未确认清除时，该餐次的引用不会被提交或改写；确认清除后，只有该餐次会随保存更新。旧版列表仍维持原有数组形态，旧服务器不能证明菜品完整时，新 Web 会禁止修改餐次，但允许编辑其他字段。旧客户端仍可能因自行替换餐次而丢失不可见引用，部署前需验证兼容性。

纪念日菜单按浏览器本地日期分为即将到来、往日和日期待核对，并支持按标题、主题、备注或可读取的菜品搜索。筛选在已加载列表内进行，不更改服务器记录；列表目前仍一次读取全部菜单，数据量很大时并非服务端分页。编辑草稿被筛选隐藏时会显示继续编辑入口，创建结果不确定时刷新核对会清除筛选，但仍需要用户自己检查；未看到记录不代表先前请求不会稍后完成。

新版 Web 删除菜单时要求服务端明确提供 `supportsConditionalDelete`，并携带原版本。若记录在确认期间被编辑或删除，条件删除不会匹配，页面提示刷新核对；旧服务器没有该能力时会禁用删除。删除菜单只删除数据库记录，不会自动清理上传文件。

旧客户端不发送版本时仍可以更新或删除菜单，服务器会在更新时生成新修订标记，使此前打开的新版 Web 草稿发生冲突；但旧客户端自己的无条件操作仍可能覆盖或删除其他人的更新。直接数据库写入、绕过应用层钩子的批量操作，以及同时运行未升级的旧服务器实例，也不受修订标记保护。迁移时应协调服务版本并保留私有备份；不要将此功能理解为覆盖所有外部写入的事务或锁。

部署前在隔离环境验证并发更新、历史记录、图片引用与移动端兼容性，完成数据库和上传文件的备份恢复演练。旧服务器不应因这项改动被自动部署或修改。
