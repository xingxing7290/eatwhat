# 排餐家庭隔离与不可用菜品

首页、日历、每日安排和周计划读取时，仅填充当前家庭的菜品与添加者。历史引用指向其他家庭或已删除对象时，保留原餐次并显示“菜品不可用”，不会自动删除数据库中的原引用。新 Web 在该餐次无法完整读取时禁止保存选择；周计划仍可查看和生成草稿，但不能应用，直到用户在日历中核对并明确清除相关餐次。

购物清单生成遇到不可用菜品时返回 `SCHEDULE_MEAL_UNAVAILABLE`，不会生成不完整的清单或覆盖已有食材。检查与后续写入不是事务，家人或旧服务并发修改期间仍可能发生变化；直接数据库写入和旧版客户端自身的无条件替换也不受新版 Web 的操作保护。不要在未备份、未验证的情况下直接更改旧服务器。

每日接口的移动端精简响应也会在不可用引用处返回 `meal: null`，以保持餐次位置且不暴露外家资料。部署前需验证实际移动客户端是否能安全处理这种历史异常数据；不能仅凭接口测试断言所有旧版本均兼容。
